Emmanuel Effiom DukeAI engineer

LLM products, agents and evaluation tooling, built end to end and shipped.

I build AI systems that have to work outside a notebook: products with real users, adversarial inputs, API budgets and failure modes that don't announce themselves. My approach is the same whether it's a security product or a forecasting pipeline. Separate what can be checked deterministically from what needs a model. Treat model output as something to validate, not trust. Measure before tuning.

What I build

  • LLM products. Teger AI pairs deterministic signal extraction (urgency, credential and payment requests, authority claims, URL shape) with AI forensic analysis. It validates every result against a typed schema and treats each message as attacker-controlled input.
  • Agents and multi-model pipelines. My Metaculus forecasting bot runs parallel retrieval across several search providers, synthesises a research brief, and combines a weighted five-model ensemble with critic and red-team passes.
  • Evaluation and reliability tooling. An offline harness that replays calibration variants against 190 resolved questions at zero token cost. A leak canary for date-bounded backtests. A probe that measures each model's real knowledge cutoff instead of trusting its self-report.
  • Full-stack AI applications in fintech, agriculture and geospatial analysis, from backend APIs to the interface.

How I work

Most AI failures I've debugged were silent: a research provider failing without crashing, a quality signal stuck at its maximum, a calibration step biasing every forecast the same way. So I log what each component actually did, keep secrets server-side, rate-limit public endpoints, and build small, cheap evaluations before scaling anything. I write up the results, including the negative ones.

Tools

Python, TypeScript and JavaScript, FastAPI, React, Chrome extensions, OpenRouter and multiple model providers, retrieval and search APIs, Pydantic schemas, GitHub Actions CI, and PyTorch for research work.
